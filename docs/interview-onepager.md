## 30 秒开场（背这一段）

> 我做了一个旅拍方案 Agent。它解决的核心问题是：LLM 生成的行程看起来很美但不可执行——一天排五个外景、景点名是编的、妆造排在拍摄之后。我的做法是把「可执行」拆成 12 条硬约束，判定放在确定性代码里，模型只负责生成；生成前先算需求可不可满足，不可满足就结构化拒绝；生成后不过模型校验，报告回喂做定向修复，且只有严格变优才接受。质量不是感觉：80 个主集用例、200 个盲测 brief、一个故意犯错的对照 provider，分数跨 Python 3.10–3.13 逐位一致。

## 五个必考问题（30 秒版答案）

1. **为什么判定不交给模型？** 时序、算术、预算是确定性运算，模型不稳定也不必参与；判定放代码里，分数才能跨模型跨版本比较，才能写单元测试。
2. **修复会不会越改越差？** 会，所以有单调保护：只有 `(hard_pass, score)` 严格变大才接受。用三种构造 provider 做过实验：会读报告的 69/69 成功，忽略报告的 69 次全被拒，故意越修越差的 69 次全被拦。
3. **0.98 分是不是太完美？** 离线 provider 照着规则写，高分是上限参考不是效果宣传；对照组 naive 只有 0.30，说明尺子分得出好坏；真正的压力测试在接真实模型之后。
4. **你这不是 Agent 吧？** 如实承认：是确定性流水线，没有多轮工具调用，所以也不存在工具死循环。加循环的条件是「下一步查什么无法预知」（比如真实商家档期），到那时我会加，且给重试上限 + 墙钟预算——预算这条现在就有。
5. **异步快 3 倍为什么不默认开？** 因为默认值是承诺：项目写过「每个被接受的请求都已落库」。async 的持久性边界是硬杀时队列里的行会丢——这个窗口我用子进程真杀量过，有界可数；把收益和代价都写给部署方选，而不是我替他选完继续用原口径宣传。

## 主动交代的边界（先说比被问出来好）

- 离线 `good` provider 是按规则写的，代表当前规则的上限参考；**真实模型数据还没有**，那是阶段 4。
- 性能数字全部单机 loopback；同机不同批次「关掉写库的加速比」测出过 2.48× / 11× / 5.13×，所以只信**同批内**相对比较，拿回比例（45–47%）比绝对倍数稳。
- `async` 模式断电/被杀会丢队列里未提交的行；默认仍是 `sync`。
- 知识库是人工整理的小样本（五座城市），不是实时商家/票价数据。

## 现场可跑（离线，无需任何 key）

```bash
python -m pip install -e ".[api,dev]"
python -m shotplan.cli rules                                   # 12 条硬约束
python -m shotplan.cli plan --hours 3 --budget 800             # 预算不足时的结构化拒绝
SHOTPLAN_PERSIST_MODE=async python -m shotplan.cli serve       # 「运行统计」页看写入积压
python -m evals.run_eval --write-report                        # 评测报告（退出码即门禁）
```

# 记录本身也要被检查

> 由 `python scripts/kb.py --check` 守住。生成页：[kb-health.md](kb-health.md)、[next.md](next.md)、[HANDOFF.md](HANDOFF.md)。

项目里已经有门禁管**产出**：评测报告、门禁数量、知识库数据新鲜度、README 里的数字。
没有门禁管**「为什么这些结论成立」的记录**——60 多份文档互相引用代码、实验和彼此，
18 份 ADR 的推理只以散文形式存在。

这份机制补的就是这一段。它不产生新知识，只让已有记录里的问题变得可见。

## 两个真实故障，不是假设

**一、手写的状态文档一天就过期。**
`docs/HANDOFF.md` 曾手写「27 道门禁、68 个地点、19 个新提交」。第二天实际是 30 道门禁、67 个地点。
手写状态文档在提交的那一刻就开始腐烂，唯一的长期解法是生成它。

**二、代码删了，文档还在指。**
`docs/optimization-report.md` 引用 `_source_ref_exists()` 与 `_flatten()`，两个函数都已不存在。
链接检查器看不见反引号里的名字，类型检查器不看文档，于是没有任何东西会红。

## 只检查能机械判定的东西

第一版把「反引号里像标识符的东西」全当引用，1027 个 token 里 888 个解析失败，
误报率 86%——规则名、配置键、概念词全被当成了代码符号。这样的门禁第一天就会被关掉。

现在的范围按「有没有确定的解析器」划线：

| 引用类型 | 写法 | 解析方式 | 失效时 |
| --- | --- | --- | --- |
| 文件路径 | `` `src/shotplan/timeline.py` `` | 文件是否存在 | 失败 |
| 函数 / 类 | `` `align_light_window()` `` | 仓库内是否有 `def` / `class` | 失败 |
| 实验编号 | `E01` | 是否在 `evals/experiments.jsonl` | 失败 |

三个解析器都有明确答案，所以它们可以让 CI 变红。其余一律只报告。
改写省略写法（`v1..v6-naive.json`）、gitignore 的产物目录、以及 PromQL / 内置函数
都在解析前排除——这些是第一轮实测出来的假阳性，不是猜的。

## 不按「文档年龄」排序

把旧文档列出来是没用的：稳定的系统会产生又老又正确的文档，按年龄排序只会训练读者忽略这份报告。
文献里预测腐化的配对指标是**背离**——代码在动、描述它的文档不动
（[documentation freshness metrics](https://datadef.io/guides/en/documentation-freshness-metrics)）。
所以这里用「文档引用的 `.py` 在文档之后还有没有提交」来排序。

这条只在本地 `--queue` 里生效：CI 默认浅克隆（depth 1）没有历史可比，
脚本会直接说「没有可用的 git 历史」，而不是假装没有漂移。

## 决策索引：把「什么时候该改主意」变成字段

ADR 的通病是记下了决定，没记下**什么情况下这个决定该失效**。
一句常被引用的话是：没有这一节的记录不是决策，是盖了日期的教条
（[ADR lifecycle](https://sekin.in/the-adr-that-rots-isnt-the-decision-its-the-assumption-under-it)）。

`docs/decisions.jsonl` 给关键 ADR 补上机器可读的索引：

```json
{"id": "D02", "adr": "docs/adr/0002-validator-outside-model.md",
 "decision": "硬约束由确定性代码判定", "evidence": ["E01", "E06"],
 "breaks_if": ["连续 3 批、每批至少 100 例真实模型输出，硬通过率均 ≥99%，且人工抽检 30 例无漏判"],
 "status": "active", "reviewed": "2026-11-17"}
```

`breaks_if` 必须是可观测事件，不能是「以后再说」「必要时」。
脚本会对这类措辞告警。它还会交叉检查：**某条决策引用的实验如果已被推翻，这条决策就浮出来**——
依据倒了而决策还挂着，是这套机制最想抓的东西。

覆盖率目前是 5/18。没索引的 ADR 不是错的，只是还没写出失效条件；这个数字会如实显示，不硬凑。

## 三个输出

| 文件 | 回答什么 | 谁看 |
| --- | --- | --- |
| [kb-health.md](kb-health.md) | 哪些引用失效、每条结论靠什么站住、哪些实验无法判定 | 想判断某句话可不可信时 |
| [next.md](next.md) | 现在该做什么，按「能不能机械判定」分 P0–P3 | 每次开工前 |
| [HANDOFF.md](HANDOFF.md) | 规模与状态、先读什么、别做什么 | 换人 / 换模型时 |

三份都是生成的，`--check` 会比对磁盘与数据的差异，手改会红。

## 维护

**加一条决策**：在 `docs/decisions.jsonl` 追加一行。`adr` 必须指向真实文件，`evidence` 必须是台账里的实验编号，`breaks_if` 至少一条。

**豁免一处引用**：在 `docs/kb-allow.json` 里登记 `doc` + `token` + `reason`。
必须写理由——豁免不是删除，是让技术债有名字。当前四条，来自两份文档：
一份历史报告在描述当时存在的函数，一份（就是本文）把它们当反例提及。

**加一项检查**的前提：能机械判定，且在真实语料上误报率低于 5%。达不到就只做报告，不做门禁。

## 它检测不到什么

- **语义反了**：文档引用的函数都存在，但描述的行为与代码相反。三类解析器都看不出来。
- **引用正确但过时**：`E03` 确实存在，但文档拿一条已被推翻的实验当依据——这个只能靠人读 `verdict` 列。
- **没写下来的东西**：整套机制只检查已经写下的记录。最重要的缺口往往是没被记录的那个决定。
- **多轮 / 长期**：没有跨会话的记忆，每次都是重新读文件。这是有意为之——可核验优先于聪明。

上面四条都无法用脚本补。它们只能靠一条纪律：**写下结论时顺手写下它依赖什么**。

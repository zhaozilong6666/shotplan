# 哪个常量扰动才会改变结果

基线：主集 80 条，通过 69，均分 0.8421。下表把每个常量乘 0.5 与 1.5 各跑一遍，记录「由通过变失败」的条数——这是比均分更硬的信号，因为它直接说明方案还能不能用。

| 常量 | 控制 | 基准值 | ×0.5 | ×1.5 | 变失败（×0.5 / ×1.5） | 平均地点数 | 均分（基准 → ×0.5 → ×1.5） |
| --- | --- | ---: | --- | --- | --- | --- | --- |
| `MIN_TRANSFER_MINUTES` | hard:TRANSFER_BUFFER | 20 | 10 | 30 | 0 / 3 | 1.55 → 1.59 → 1.51 | 0.842 → 0.848 → 0.804 |
| `STYLING_FLOOR_MINUTES` | indirect | 60 | 30 | 90 | 0 / 3 | 1.55 → 1.55 → 1.51 | 0.842 → 0.845 → 0.807 |
| `MIN_SHOOT_BLOCK_MINUTES` | soft:SHOOT_TOO_SHORT | 60 | 30 | 90 | 0 / 0 | 1.55 → 1.55 → 1.55 | 0.842 → 0.842 → 0.842 |
| `STYLING_SHARE` | indirect | 0.35 | 0.175 | 0.525 | 0 / 0 | 1.55 → 1.59 → 1.55 | 0.842 → 0.847 → 0.840 |
| `MAX_OVERRUN_MINUTES` | hard:TIME_OVERRUN | 15 | 8 | 22 | 0 / 0 | 1.55 → 1.55 → 1.55 | 0.842 → 0.842 → 0.842 |
| `MIN_FEASIBLE_HOURS` | gate:feasibility | 1.5 | 0.75 | 2.25 | 0 / 0 | 1.55 → 1.55 → 1.55 | 0.842 → 0.842 → 0.842 |

## 读法

先看「控制」这一列，它决定了该不该期待通过率变化：6 个常量里只有 2 个直接参与硬判定（`MIN_TRANSFER_MINUTES` → TRANSFER_BUFFER、`MAX_OVERRUN_MINUTES` → TIME_OVERRUN）。`MIN_SHOOT_BLOCK_MINUTES` 对应的是 **soft** 规则 SHOOT_TOO_SHORT——它影响分数，不影响通过。所以 E19 那句预测「它会让 ≥10 条 brief 从通过变成失败」从一开始就不可能成立：soft 规则不会让 `hard_pass` 变 False。

按控制类型分开看更清楚：

- **hard 类**：最多 3 条 brief 从通过变失败（占 80 条的 4%）。
- **soft 类**：变失败 0 条（定义使然），均分变化 0.000——连分数都没动。这说明这批 brief 的拍摄块都远大于 90 分钟，扰动根本没跨过 soft 门槛。拿通过率衡量 soft 规则是用错了尺子；连分数都不动，说明连 soft 的尺子都没碰到。
- **可行性常量** `MIN_FEASIBLE_HOURS`：决定 11 条 infeasible 的判定，±50% 没有跨过任何 brief 的边界，所以 0 条变化——它是对的，只是这个评测集里的 brief 离边界都太远。

修正后的结论：**在硬判定层面，评测集对 hard 常量的 ±50% 扰动分辨力很低（最多 3 条）**。原因见 E20：方案每次都被排满，而最小调整单位是一个地点（60 分钟以上），5–20 分钟的扰动跨不过那一档。但这不能推广到 soft 常量——它们本来就不该改变通过率，拿通过率去衡量它们是用错了尺子。
## 这解释了前两条实验

E17/E18 花了两次测量去选转场估计的模型，结果在 320 条盲测上一条都没变。原因就在这里：`MIN_TRANSFER_MINUTES` 在 ±50% 内只影响 3 条。**如果先跑这张表，那两次实验的时间可以省下来**——这张表应该放在任何参数实验之前。

## 一个测量方法上的教训

第一版这个脚本用 `value * factor` 扰动，把 `20` 变成了 `20.0`。浮点分钟破坏了下游所有比较与格式化，结果两个方向都报 69 条失败——那不是敏感性，是类型错误。「扰动实验必须保持被扰对象的类型」这条，比任何结论都值得记住。

## 局限

只扰动 ±50%，只测主集，只改一个常量。真实改动常常是多个参数同时动，而且这张表说明的是「在这个评测集上能不能测出差别」，不是「这个参数不重要」。

# 哪个常量扰动才会改变结果

基线：主集 80 条，通过 69，均分 0.8421。下表把每个常量乘 0.5 与 1.5 各跑一遍，记录「由通过变失败」的条数——这是比均分更硬的信号，因为它直接说明方案还能不能用。

| 常量 | 基准值 | ×0.5 | ×1.5 | 变失败（×0.5 / ×1.5） |
| --- | ---: | --- | --- | --- |
| `MIN_TRANSFER_MINUTES` | 20 | 10 | 30 | 0 / 3 |
| `STYLING_FLOOR_MINUTES` | 60 | 30 | 90 | 0 / 3 |
| `MIN_SHOOT_BLOCK_MINUTES` | 60 | 30 | 90 | 0 / 0 |
| `STYLING_SHARE` | 0.35 | 0.175 | 0.525 | 0 / 0 |
| `MAX_OVERRUN_MINUTES` | 15 | 8 | 22 | 0 / 0 |
| `MIN_FEASIBLE_HOURS` | 1.5 | 0.75 | 2.25 | 0 / 0 |

## 读法

最多的一条是 `MIN_TRANSFER_MINUTES`，上下浮动 50% 只让 3 条 brief 从通过变成失败。其余 4 个常量在 ±50% 内一条都不变。

也就是说：**这个评测集对参数扰动几乎不敏感**（最多 3 条，占 80 条的4%）。不是「这个常量不重要」，而是「用当前评测集分辨不出它的精确值」。两种可能的解释，都值得记下来：

1. **排期有余量**：brief 给的时长通常比方案实际需要多 1–2 小时，转场 +10 分钟、拍摄块 +30 分钟都还在余量里，因此不改变「通过/不通过」这个二元结果。
2. **通过与否由别的机制决定**：11 条 infeasible 的拒绝、评分下限、结构性的硬约束检查——这些不在这 6 个常量的控制范围内。

无论哪一条，实践含义相同：为这些常量建模、调参、做实验，收益都很低。要让参数变得「可测」，得先让评测集里出现对时长更紧的 brief——那是评测集的问题，不是参数的问题。

## 这解释了前两条实验

E17/E18 花了两次测量去选转场估计的模型，结果在 320 条盲测上一条都没变。原因就在这里：`MIN_TRANSFER_MINUTES` 在 ±50% 内只影响 3 条。**如果先跑这张表，那两次实验的时间可以省下来**——这张表应该放在任何参数实验之前。

## 一个测量方法上的教训

第一版这个脚本用 `value * factor` 扰动，把 `20` 变成了 `20.0`。浮点分钟破坏了下游所有比较与格式化，结果两个方向都报 69 条失败——那不是敏感性，是类型错误。「扰动实验必须保持被扰对象的类型」这条，比任何结论都值得记住。

## 局限

只扰动 ±50%，只测主集，只改一个常量。真实改动常常是多个参数同时动，而且这张表说明的是「在这个评测集上能不能测出差别」，不是「这个参数不重要」。

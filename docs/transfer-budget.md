# 20 分钟够不够转场：一个上下界，不是一个答案

调度器把每一次转场都当成 `MIN_TRANSFER_MINUTES = 20`，而知识库里每个地点都记了「从市中心过去要多久」。这两件事没有必然关系，也没有任何检查对照过它们。

数据只有每个地点到中心的一个数，两点之间的距离需要两个维度，所以算不出真实值。但三角不等式给了一个括号：`|a−b| ≤ 两点时间 ≤ a+b`。于是每对地点落入三类之一：

- **必然不够**：`|a−b| > 20`，任何自洽的几何下转场都超过 20 分钟；
- **必然够**：`a+b < 20`，怎么走都短于 20 分钟（这意味着常量在此偏松，无害）；
- **可能**：区间包含 20——注意「可能」不等于「对」。

## 汇总：248 对地点

| 分类 | 对数 | 占比 |
| --- | ---: | ---: |
| 必然不够 | 21 | 8% |
| 必然够 | 0 | 0% |
| 可能（区间含 20） | 227 | 9153% |

**区间包含 20 分钟的比例是 92%**，这是那条假设的实测值。它成立的含义只有一层：这个常量对大多数地点对不是明显错的。它不成立的含义则很硬：如果多数配对连「可能」都算不上，常量就该改。

## 哪些配对必然不够

- **西安**：1 对（占该城 4%）
- **洛阳**：7 对（占该城 25%）
- **杭州**：5 对（占该城 18%）
- **苏州**：1 对（占该城 4%）
- **成都**：3 对（占该城 8%）
- **北京**：4 对（占该城 11%）

这些配对说明常量在结构上偏小，而不是碰巧偏小：只要一地在城郊（到中心 40 分钟）、另一地在城里（10 分钟），|a−b| 就是 30，20 分钟必然不够。修法不是把 20 调大——那会让市中心的短转场也被迫留出 40 分钟——而是让转场时间按地点算，知识库已经有需要的那个数了。

## 这个测量不能证明什么

它只能证明「20 分钟不是明显不够」，不能证明「20 分钟够」。反过来说，它也不能证明「按地点算时间」更好——那需要真实的城市路网数据或一次实测，而这里两者都没有。

如果要把它变成真正的测量：给知识库的每个地点补经纬度，用球面距离除以该城市的实测平均车速，再和调度器的固定值对比。那是另一条实验，不是这一条的延伸。

命令：`python -m evals.real_model_lab --write` ｜ 数据源：`evals/real-model.json` ｜ 历史对照：[real-model-comparison.md](real-model-comparison.md)

模型 `deepseek-v4.1-flash-1017`（https://www.wujie-api.com/v1，temperature 0.2，并发 4）｜ prompt `planner-v2` ｜ 80 个用例，其中 69 个需要生成方案

## 结论摘要

真实模型在 **69 个需要生成方案的用例**上硬约束通过率 **94.2%**（65/69），平均得分 **0.8424**，最低 0.7625。

**首次输出即可用率 91.3%**（63/69 未触发修复），发生修复 3 次，异常 3 次。这个数字比平均分更能说明结构化输出的稳定性：修复循环会把一次失败掩盖成一个还不错的分数。 异常用例：C21, C40, C51（流水线降级为 error，既不是好方案也不是坏方案，所以不计入最低分）。

## 这份数据不能证明什么

- 单模型单轮采样：temperature 0.2 仍有随机性，重跑的数字会小幅波动；要比较两个 prompt，必须用同一批用例、同一模型、连续跑，并把两轮都记下来。
- 成本按 `agents/openai_compatible.py` 里的价目表估算，不是账单；只用于相对比较。价目表未收录的模型会退到默认价，可能与实际计费相差数倍。
- 主集共 80 个用例，覆盖 5 城 × 多风格 × 预算/时段压力；本次实际取样见上方用例数，两者都不代表开放域真实需求分布。
- 离线规则 Agent 的 100% 不是「更强」，而是它被设计为不可能违反硬约束；两者的差距说明的是**校验器有判别力**，不是模型好坏排名。

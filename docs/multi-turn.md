用例 **12** 条，当前通过 **12** 条（**100%**）。

这是规则**当前的状态**，不是首次运行的记录。首次跑是 5/12，每个修复各补上几条见 [multi-turn-attribution.md](multi-turn-attribution.md)。

本页由 `evals/multi_turn_lab.py` 生成。被测对象是 `followup.py` 的确定性规则，不调用任何模型，因此结果可复现、可归因：失败即规则缺口。

| 用例 | 类型 | 结果 | 说明 |
| --- | --- | --- | --- |
| M01 | shorter | 通过 | 用「砍」表达缩短，动词不在白名单里 |
| M02 | cheaper_amount | 通过 | 带金额的降价，应该算出新预算而不是只记一条偏好 |

| M04 | style_replace | 通过 | 否定并替换风格，styles 要真的换掉 |
| M05 | compound | 通过 | 两件事一起调，对照组：白名单本来就能过 |
| M06 | absolute_budget | 通过 | 直接给数字，没有「多/加」这类动词 |
| M07 | implicit_deadline | 通过 | 赶车是隐含的结束时间约束，不是一句闲聊 |
| M08 | cheaper_vague | 通过 | 模糊降价，没有给金额 |
| M09 | unrecognised | 通过 | 守门用例：说不清的话不能被瞎猜成某个字段 |

## 口径

- 一条用例通过 = `expect` 里每个字段都对，且最后一轮的「识别/拒答」符合预期。
- 中间轮次不单独计分，只要求最终状态正确：多轮的价值在于收敛，不在于每句都改对。
- 拒答也是正确答案之一：说不清的需求被硬塞进某个字段，比让用户改表单更糟。
- 每个修复各值多少条，见 [multi-turn-attribution.md](multi-turn-attribution.md)。

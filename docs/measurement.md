# 测量方法：这个项目怎么判断“真的更好”

结论先放前面：**在 69 个用例上，单轮结果只能可靠检测 8–11 个百分点的差异。** 任何小于这个幅度的“提升”，在统计上和噪声无法区分。本文说明这个数字怎么来的、报告里两种区间分别是什么、以及做比较时该遵守什么规则。

## 一、两种不确定性，别混为一谈

| 问题 | 方法 | 回答什么 |
| --- | --- | --- |
| 换一批**用例**，结论会不会翻？ | 对用例做自助法重采样（2000 次，固定种子） | 结论对样本构成的敏感度 |
| 换一个**时间点重跑**，数字会差多少？ | 同一批用例跑 N 轮，看轮次间极差 | 采样温度、上游波动带来的抖动 |

报告里两个都给：

- 结论摘要的 `95% CI` 是**第一种**
- 「重复测量」小节的**轮次极差**是**第二种**

把第一种当成第二种，是“单轮跑完就宣布提升”的常见来源。

## 二、当前能力边界（`python -m evals.power`）

通过率 0.94、用例级得分标准差 0.08 的设定下：

| 想检测的差异 | 非配对需要 | 配对需要（同一批用例） |
| --- | ---: | ---: |
| 2 pp | 2214 | 1107 |
| 3 pp | 984 | 492 |
| 5 pp | 355 | 178 |
| 10 pp | 89 | 45 |

反过来问“69 个用例能检测多大差异”：

| 设计 | 通过率 | 平均分 |
| --- | ---: | ---: |
| 非配对 | 11.3 pp | 0.038 |
| 配对 | 8.0 pp | 0.027 |

**配对能把需求砍半**，因为用例难度在两种条件下抵消了。这也是评测必须用同一批用例、同一温度、交替执行的原因——不是为了好看，是为了省钱。

## 三、决策规则

写进评审流程，避免每次靠感觉：

1. **单轮结果只能用于发现“大问题”**（≥10pp 的退化），不能用于排名。
2. 比较两个配置时，必须**配对**：同一批用例、同一模型、同一温度，A/B 交替跑。
3. 报告差异时同时给**点估计与区间**；区间跨 0 就说“测不出差异”，不写“略好于”。
4. 想检测 3–5pp 的改进，先按上表扩样本，否则不要开实验。

## 四、这条规则推翻了什么

项目早期的三轮对照里，`deepseek-chat` 并发 4 与并发 2 的通过率差 **4.4 个百分点**（89.9% vs 85.5%）。按上表，69 个用例的配对检测下限是 8.0pp，**这个差异在检测能力之外**。

因此正确表述是：「同一模型在两轮里观察到 4.4pp 差异，但该差异小于当前样本的可检测下限，不能归因于并发或模型变化」。原报告里的“并发不同导致波动”属于过度解读，已在 [failure-taxonomy.md](failure-taxonomy.md) 中更正。

## 五、复现

```bash
# 单轮（原有行为，报告给用例级 CI）
python -m evals.real_model_lab --write

# 重复测量（报告给轮次极差 + 用例级 CI）
python -m evals.real_model_lab --repeat 3 --concurrency 4 \
  --write --out evals/real-model-repeat3.json --report-path docs/real-model-repeat3.md

# 样本量
python -m evals.power --pass-rate 0.94 --score-sd 0.08 --paired
```

`bootstrap_ci` 用固定种子，`--render` 可以只重渲染不调模型，所以报告与快照的对应关系可校验（`--check`）。

## 六、一次失败的实测：断供被误当成质量下降

第一次 `--repeat 3` 全量跑（240 次调用）的结果是：通过率 66.7%、平均分 0.5953、**68 个 error**、耗时 6425 秒、成本 ¥19.35。看起来像模型崩了。

实际原因：中转站余额耗尽，后半程全部返回 `403 INSUFFICIENT_BALANCE`。由于每次调用会重试 3 次、每次等 120 秒，故障被放大成了近两小时的等待和一批“0 分”样本。

三个教训，已经写进代码：

1. **评测器必须能察觉上游挂了**：新增 `--max-error-rate`（默认 25%）与 `--min-calls`，超过阈值立即中止且**不写快照**——用“没有结果”代替“错误的结果”。
2. **错误要按原文分类**：报告新增「异常分布」表，把 `INSUFFICIENT_BALANCE` / `401` / `timeout` 与字段缺失、非法枚举分开。只看 `errors: 68` 无法区分这两类。
3. **长任务必须有进度与 ETA**：每 N 次调用打印完成数、错误数与预计剩余时间。没有它，1 小时的异常等待和 1 小时的正常运行看起来完全一样。

被污染的产物留在 `evals/out/contaminated-repeat3.*`（不进入报告），作为这次事故的证据。

## 七、还没做到的

- **没有做配对 A/B 的 prompt 对比**：需要 `planner-v3`，且要交替执行，属于下一阶段。
- **区间只覆盖用例抽样**，不含模型采样（temperature）。轮次极差补上了这一块，但 N=3 只能给出粗略范围，不是严格方差估计。
- **没有做多重比较校正**：一次比较多个指标时，假阳性率会上升；当前报告只比较两个主指标，暂未处理。

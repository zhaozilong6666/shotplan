## 项目经历（可直接复制）

**shotplan —— 可评测、带硬约束校验的旅拍方案 Agent**（个人项目 · Python / FastAPI / SQLite · [GitHub](https://github.com/zhaozilong6666/shotplan)）

> 输入一段旅拍需求，输出时间轴、花费、备选方案俱全的可执行行程；用确定性校验替代 LLM 自评，让"方案能不能执行"变成可回归测试的工程问题。

- 设计「生成前可行性判定 → 检索 → 生成 → 解析 → 校验 → 有界修复」六段流水线：15 条确定性规则（10 条硬约束 + 5 条软评分，覆盖时序冲突、转场不足、预算超支、地点幻觉、必去/排除地点等）由**不经过模型的代码**判定，校验报告转成修复提示回喂，且只接受严格变优的新草稿；80 例离线对照中规则 Agent 平均分 **0.9796**，naive 基线 **0.2974**。`deepseek-v4.1-flash-1017` 同集实测（temperature 0.2、并发 4）：69 个需生成用例中 **65 个硬约束通过（94.2%）**，平均分 **0.8424**，**首次输出即可用 63/69（91.3%）**，3 例因模型自造字段（缺 `location_id`、非法 `activity`）被解析层拒绝；单次 P50 44.3s、P95 89.7s。单轮采样结果与限制见 `evals/real-model.json`、`docs/real-model.md`。
- 修复信任边界真实缺陷：模型输出 `"免费"` 使 `int()` 抛 `ValueError` 绕过编排层导致 **HTTP 500**；重构解析层（括号配平扫描、多候选对象消歧、有 trace 记录的格式修复、数字绝不猜），并用 **300 次确定性变异测试**守住「异常只允许是 ParseError」的契约。
- 针对"同步写库是关键路径最大开销"的实测结论，实现**写后置队列**（进程内单写线程 + 批量事务 + 队列满退化为同步写）：`off/sync/async` 三组同批对照显示异步相对同步 **2.96×**、P95 **186ms→93ms**、**三组 0 丢写**；进程被硬杀的丢失窗口用子进程 `os._exit` **实测**而非推断，默认仍保持同步写的持久性承诺。
- 修复循环从"只数重试次数"升级为**墙钟预算**（原最坏 183s：2 次生成 × 3 次 HTTP 尝试 × 30s 超时），超预算时降级返回当前最优草稿；把流水线写成 `STAGES` 状态表，Mermaid 图与逐节点输入输出**由代码生成**，CI 比对文档漂移，测试断言运行时事件全部来自这张表。
- 建立可复现的质量体系：80 个主集用例 + **320 个盲测挑战 brief**（挖掘器不读取任何期望输出）+ 527 条结构化失败记录；用 **8 处受控变异**验证门禁本身，发现旧门禁漏掉 4/8 处校验端削弱并修复；最终 **27 道 CI 门禁、470 个单测、93.02% 覆盖率、Python 3.10–3.13 四版本矩阵**。

## 技能清单（并进技能栏）

- **语言/框架**：Python（标准库优先的分层架构）、FastAPI / uvicorn、原生 JS（无构建前端）
- **数据/并发**：SQLite（WAL、批量事务、单写者争用调优）、线程 vs 进程、有界队列与背压
- **工程化**：pytest / 覆盖率 / 变异测试、确定性模糊测试、GitHub Actions 多版本矩阵、httpx 真实服务压测
- **LLM 工程**：prompt 版本化管理、结构化输出容错解析、修复循环（repair loop）设计、LLM 输出信任边界

## 面试一句话定位

> "这个项目最有说服力的不是功能，而是**判定与测量的方式**：模型不负责判定对错，门禁自己被变异测试攻击过，性能结论来自对照实验而不是推断，连'异步化会丢多少数据'都是用真杀进程量出来的。"

## 提醒（给自己）

- 真实模型结果为单轮、单模型测量：C21/C40/C51 三例是模型输出不合规被拒（缺字段、自造 activity），不是超时。不能把 94.2% 说成稳定或生产级成功率。同模型换个并发，通过率能差 4.4 个百分点，所以不要拿单轮排名。三轮对照见 [real-model-comparison.md](../real-model-comparison.md)，逐例数据在 `evals/real-model.json`。
- 成本数字是按代码内价目表估的，不是账单；该模型中转价目未收录时按默认价计算，会明显高估，面试时不要直接报金额，改报 token 量。

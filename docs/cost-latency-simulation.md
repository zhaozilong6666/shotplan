# 成本与延迟模拟报告

> 这是一份**配置驱动的模拟**，不是真实模型测量。token 由离线 provider 估算，延迟是价格卡里的配置值；接入真实模型后请用同样的表格记录实测值。

同一批 **50** 个用例（含无法满足的 brief，它们不调用 provider、成本为 0）。

## 价格卡与结果

| 模型 | 输入价 /1K | 输出价 /1K | 模拟延迟 | 调用次数 | token in / out | 估算总成本 | 单次成本 | P50 / P95 | 通过率 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| `gpt-4o-mini` | 0.0011 | 0.0043 | 800 ms | 42 | 27676 / 15625 | 0.09763 元 | 0.002325 元 | 800.09 / 800.2 ms | 100% |
| `deepseek-chat` | 0.002 | 0.008 | 1200 ms | 42 | 27676 / 15625 | 0.180352 元 | 0.004294 元 | 1200.09 / 1200.18 ms | 100% |
| `gpt-4o` | 0.018 | 0.072 | 2500 ms | 42 | 27676 / 15625 | 1.623168 元 | 0.038647 元 | 2500.09 / 2500.23 ms | 100% |

## 预算换算（估算）

| 模型 | 每天 100 次 | 每月按 22 天 |
| --- | ---: | ---: |
| `gpt-4o-mini` | 0.2325 元 | 5.115 元 |
| `deepseek-chat` | 0.4294 元 | 9.4468 元 |
| `gpt-4o` | 3.8647 元 | 85.0234 元 |

## 这验证了什么

1. 成本从 provider 的 token 与价格卡一路传到 `trace`、评测聚合、报告与运行统计，没有断点。
2. 延迟的 P50/P95 聚合与分组在真实模型接入前就已经可用。
3. prompt 版本通过 `PriceCard.prompt_version` 进入每次 trace，接真实模型后可直接对比 v1/v2 的性价比。
4. 预算换算能在花真钱之前给出量级，避免第一次跑评测就把额度烧完。

## 边界（重要）

- token 数是离线 provider 的字符估算，不是厂商 tokenizer 的结果；真实成本会有偏差。
- 延迟是配置值，不含网络、排队、限流与重试。
- 质量列（通过率/均分）来自规则 provider，与成本无关；真实模型的质量通常更低，这正是 `docs/eval-report.md` 要在接模型后重跑的原因。
- 结论只能用于「量级与链路验证」，不能用于对外宣称某模型性价比。

## 复现

```bash
python -m evals.cost_latency --write-report
```

报告与 `evals/out/cost-latency.json` 均由代码生成，请勿手工编辑。

# 它为什么还不够聪明，以及下一步怎么走

> 2026-11-15。缘起一句很准的评价：「感觉还是不是很智能，道阻且长」。
> 本文不辩护，把缺口拆开，标清哪些已经补上、哪些还差得远。

## 一句话诊断

**这个系统的智能主要在「判卷」，不在「做题」。**

校验器有 15 条规则、分项打分、修复循环、失败归因、盲测挑战集——它非常擅长
判断一份方案哪里不行。但「想出一份好方案」这一步，本质上还是把检索到的候选地点
填进固定槽位：候选由标签检索给出，槽位由模板定死，模型只负责排序和补文案。
所以它能稳定地不犯错，却很难给人「它懂我」的感觉。

这不是模型够不够强的问题，是**生成被架构框住了**。

## 四个具体的「不智能」

| 体感 | 结构性原因 | 状态 |
| --- | --- | --- |
| 一上来就是六个表单字段 | 输入层要求人把意图翻译成结构化参数 | **本轮已补**：一句话入口，见下 |
| 说「温柔的氛围感」毫无反应 | 系统只认城市/日期/时长/预算/风格，美学词汇无处落地 | **本轮已补**（低置信推断，会显式标出） |
| 说「不行」就完了 | 预检只做布尔拒绝，没有协商 | **本轮已补**：可点选的最小改动，且每项实跑预检 |
| 只给一个方案，没有取舍 | 单路径生成，不探索备选，也不解释「为什么是这几个点」 | **本轮已补**：三策略对比 + 可量化取舍 + 有依据的推荐 |
| 改一句话要重填 | 无会话记忆、无上下文、无追问闭环 | **未做** |

## 本轮补上的三层

### 1. 听懂一句话（`shotplan/brief.py`、`POST /api/understand`）

真实客户说「国庆去西安拍唐风，预算一千五，最好上午收工，人少一点，别去大唐芙蓉园」，
系统解析出 8 个字段，**同时把每个字段的来源摊开**：

| 来源 | 含义 | 例 |
| --- | --- | --- |
| `stated` | 原话明说 | 城市=西安、预算=1500、排除=大唐芙蓉园 |
| `inferred` | 有依据的推断 | 从「上午收工」推断 3 小时；从「温柔」推断宋制 |
| `default` | 完全没提，用默认 | 人数=1 |

关键不是解析得多准，而是**不假装确定**：推断项带证据片段与置信度，
关键时长来自推断时会主动问一句「我按 3 小时理解，对吗？」。
美学词（温柔 / 清冷 / 大气 / 氛围感）映射到风格与光线偏好，但置信度只有 0.5–0.55，
界面上标成「推断」，用户可以一键改掉。

### 2. 把拒绝变成选择（`shotplan/negotiation.py`）

原先预检说「预算 100 元、时长 1 小时 → 不可行」就结束了。
现在生成 2–3 个最小改动方案（按最低条件调整 / 留点余量），
**每个选项都重新跑一遍 `check_feasibility` 验证确实可行**才返回，
并写清代价（多花多少钱、多留多少时间）。点「采用」直接回填表单。

### 3. 诚实边界

这一层是**确定性规则解析，不是大模型理解**。它的优点是零依赖、可复现、
不花钱、每条推断都可审计；天花板也很明显：换个说法就可能听不懂，
处理不了反讽、省略、跨句指代，更不会从用户反馈里变聪明。
把它包装成「AI 理解」是不诚实的。

## 下一步（按杠杆排序）

1. ~~**多方案与取舍**~~ **本轮已完成**：`shotplan/compare.py` 一次给三份真实方案，
   差异由实际指标算出，推荐依据来自用户偏好词。
2. ~~**推荐理由**~~ **本轮已完成**：`shotplan/explain.py` 逐个拍摄块回读知识库证据
   （命中的风格标签、NOAA 黄金窗口、人流、天气、点名要求），API 的 `explanations`
   字段、CLI 与界面都会显示；理由由代码生成，不是模型自述，也不新增一次模型调用。
3. **约束协商前置到生成中**（部分完成）：`negotiation.headroom()` 已在预检通过但
   预算/时长贴近理论下限时，给出经预检复核的余量选项（`/api/understand` 的
   `headroom` 字段与界面）。更细的「2 个外景 + 简化妆造 vs 1 个外景 + 升级妆造」
   需要按候选组合实跑后测量，仍待做。
4. **会话记忆与追问闭环**：记住上一轮的偏好，用户说「再松一点」时知道指的是什么。
5. **让模型真正参与规划**：目前模型填的是固定 schema；要允许它提出检索之外的新组合，
   再由校验器把关。这一步才会真正改变「做题」能力，也最需要重新设计评测。

## 为什么按这个顺序

1–3 不依赖模型能力，能立刻改善体感且可评测；4 需要状态管理；
5 会动到「校验器是唯一真理」这个架构前提，必须配新的评测集才能做，
否则「更聪明」和「更不可控」会同时发生而无法区分。

**道阻且长是对的，但路是可以一段一段标出来的。**

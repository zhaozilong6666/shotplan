## 项目经历（可直接复制）

**shotplan —— 可评测、带硬约束校验的旅拍方案 Agent**（个人项目 · Python / FastAPI / SQLite · [GitHub](https://github.com/zhaozilong6666/shotplan)）

> 输入一段旅拍需求，输出时间轴、花费、备选方案俱全的可执行行程；用确定性校验替代 LLM 自评，让"方案能不能执行"变成可回归测试的工程问题。

- 设计「生成前可行性判定 → 检索 → 生成 → 解析 → 校验 → 有界修复」六段流水线：12 条硬约束（时序冲突、转场不足、预算超支、地点幻觉等）由**不经过模型的确定性代码**判定，校验报告转成修复提示回喂，且只接受严格变优的新草稿；评测集对照 good **0.9788** / 刻意犯错的 naive **0.3014**，证明评分器真实有效。
- 修复信任边界真实缺陷：模型输出 `"免费"` 使 `int()` 抛 `ValueError` 绕过编排层导致 **HTTP 500**；重构解析层（括号配平扫描、多候选对象消歧、有 trace 记录的格式修复、数字绝不猜），并用 **300 次确定性变异测试**守住「异常只允许是 ParseError」的契约。
- 针对"同步写库是关键路径最大开销"的实测结论，实现**写后置队列**（进程内单写线程 + 批量事务 + 队列满退化为同步写）：`off/sync/async` 三组同批对照显示异步相对同步 **2.96×**、P95 **186ms→93ms**、**三组 0 丢写**；进程被硬杀的丢失窗口用子进程 `os._exit` **实测**而非推断，默认仍保持同步写的持久性承诺。
- 修复循环从"只数重试次数"升级为**墙钟预算**（原最坏 183s：2 次生成 × 3 次 HTTP 尝试 × 30s 超时），超预算时降级返回当前最优草稿；把流水线写成 `STAGES` 状态表，Mermaid 图与逐节点输入输出**由代码生成**，CI 比对文档漂移，测试断言运行时事件全部来自这张表。
- 建立可复现的质量体系：80 个主集用例 + **200 个盲测挑战 brief**（挖掘器不读取任何期望输出）+ 517 条结构化失败记录；用 **8 处受控变异**验证门禁本身，发现旧门禁漏掉 4/8 处校验端削弱并修复；最终 **16 道 CI 门禁、263 个单测、90% 覆盖率、Python 3.10–3.13 四版本矩阵全绿**。

## 技能清单（并进技能栏）

- **语言/框架**：Python（标准库优先的分层架构）、FastAPI / uvicorn、原生 JS（无构建前端）
- **数据/并发**：SQLite（WAL、批量事务、单写者争用调优）、线程 vs 进程、有界队列与背压
- **工程化**：pytest / 覆盖率 / 变异测试、确定性模糊测试、GitHub Actions 多版本矩阵、httpx 真实服务压测
- **LLM 工程**：prompt 版本化管理、结构化输出容错解析、修复循环（repair loop）设计、LLM 输出信任边界

## 面试一句话定位

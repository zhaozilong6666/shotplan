# 红队集第一版：题是难的，但对模型不难

结论先说：**这 30 条题对 `naive` planner 是降维打击（0/24），对真实模型却不是**（95.8%）。它测出来的不是模型的上限，而是我们出题思路的盲区。

## 设计

30 条用例，24 条「可做但难」+ 6 条「必须被预检拒绝」。选题覆盖：

| 类别 | 例子 |
| --- | --- |
| 长白天光线陷阱 | 西安 11/12 小时、苏州 9 小时：正午必须有合规安排 |
| 多地点挤压 | 洛阳 4 小时跑龙门石窟 + 洛邑古城 |
| 预算贴底 | 350 元正好等于最低可执行成本 |
| 排除项冲突 | 必去城门、禁去大雁塔 |
| 输入噪声 | 未知风格 `hanfu`、空风格列表、互相矛盾的偏好 |
| 预检拒绝 | 1 小时、预算 340、拉萨、不存在的 `forbidden_city`、必去又排除、全部地点被排除 |

花钱之前先离线验过两道：`naive` 必须大面积失败（否则题太软），规则 Agent 必须大多数能过（否则题不可解）。实测 **0/24** 与 **21/24**，符合预期。

## 结果（2026-11-14）

| 指标 | 红队集 | 主集（80 例 ×3 轮） |
| --- | ---: | ---: |
| 硬约束通过率 | **95.8%**（23/24） | 94.2%（已响应 100%） |
| 平均得分 | **0.8957** | 0.8284 |
| 首次输出可用 | 20/24 | 62/69 |
| 异常 | 0 | 12（全为 502） |
| 成本 | ¥0.71 | ¥4.36 |

唯一硬失败是 **R08**：预算 400 且必须去西湖。其余 23 条一次或修复后通过。

软问题分布（`top_issue_codes`）：

| 代码 | 次数 |
| --- | ---: |
| `LIGHT_MISUSE` | 8 |
| `SHOOT_TOO_SHORT` | 2 |
| `STYLE_MISMATCH` | 1 |
| `MISSING_REQUIRED_LOCATION` | 1（修复救回 3 次、失败 1 次） |

## 三个结论

**1. 硬约束这一层已经饱和。**
主集、红队集、三轮重复，硬约束通过率都在 94%–96%。再怎么加长白天、压低预算、塞多地点，模型基本都能过。继续在硬约束上加难，边际信息量很低。

**2. 真正的弱点在软约束，而红队集没有瞄准它。**
红队 24 条里有 8 次 `LIGHT_MISUSE`，比例（1/3）和主集（26/69 ≈ 38%）一致。也就是说：**模型会把黄金光线浪费在室内或转场上，这个毛病没被红队题影响，也没被修复**。这才是有价值的方向。

**3. 「难」必须相对于某个对象定义。**
这批题对 `naive` 是 0%，对规则 Agent 是 87.5%，对真实模型是 95.8%。同一套题，三个结论。说「红队集很难」而不说对谁难，等于没说。

## 下一版怎么改

- 出题目标从「硬约束失败」改为「软问题高发」：连续长白天、黄金时段只剩室内可用、跨区转场吃掉光线窗口。
- 指标也要换：`soft_issue_rate`（有多少用例至少有一个软问题）比硬通过率更能区分。该字段已加入报告，从下一次评测开始生效。
- 保留现有 30 条作为回归集——它们证明模型在硬约束上的稳定性，这也是有用的信息，只是不该叫「红队」。

## 局限

- 单轮、单模型、单供应商；24 条的可检测下限约 17pp，95.8% 与 94.2% 的差异没有统计意义。
- R08 的失败原因未逐字段复核（只知未过硬约束），要定位需重跑该例。
- 6 条不可行用例只验证了「预检能拒绝」，没有验证拒绝理由是否准确。

# 红队 v2：瞄准软问题（2026-11-14 晚）

v1 证明了硬约束饱和，所以 v2 换目标：12 条把外景挤到上午/正午、让黄金时段被室内或
休息占掉的 brief（`evals/redteam_soft/`）。先花 3 次调用探路（¥0.13），确认
`LIGHT_MISUSE` 触发 2/3 后才跑全量 12 条（¥0.37）。

| 指标 | 主集（69 例） | 红队 v1（24 例） | 红队 v2（12 例） |
| --- | ---: | ---: | ---: |
| 硬约束通过率 | 94.2% | 95.8% | 91.7% |
| `LIGHT_MISUSE` 次数 / 用例 | 26 / 69（38%） | 8 / 24（33%） | **9 / 12（75%）** |
| 有软问题的用例 | — | — | **75%** |

v2 的软问题触发率是主集的两倍，**这才是有判别力的题集**。硬通过率依旧 92% 左右，
正好说明「硬约束通过」和「拍得好看」是两件事。

## 附带结论：v3 在这批题上翻案了

用 v2 重跑 `planner-v3`（¥0.52）并做配对比较：得分 0.8279 → 0.8710，
差值 **+0.0431（95% CI [+0.0127, +0.0763]，区间不跨 0）**，`LIGHT_MISUSE` 9 → 7。
 earlier 在饱和子集上判定「v3 无效」是被样本骗了。详见 [prompt-ab.md](prompt-ab.md)。

v2 仍不是默认：普通 brief 上看不出收益，成本却高 42–53%。下一步是按 brief 特征
做 prompt 路由，并在**新用例**上前瞻验证，不能在这 12 条上自证。

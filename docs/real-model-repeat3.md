# 真实模型实测

命令：`python -m evals.real_model_lab --write` ｜ 数据源：`evals/real-model-repeat3.json` ｜ 历史对照：[real-model-comparison.md](real-model-comparison.md)

模型 `deepseek-v4.1-flash-261017`（https://sub.7740.cn/v1，temperature 0.2，并发 3）｜ prompt `planner-v2` ｜ 80 个用例 × 3 轮，其中 69 个需要生成方案

## 结论摘要

真实模型在 **69 个需要生成方案的用例**上硬约束通过率 **94.2%**（65/69，95% CI 88.4–98.6%），平均得分 **0.8284**（95% CI 0.7735–0.8716），最低 0.7900。

**首次输出即可用率 89.9%**（62/69 未触发修复），发生修复 7 次，异常 12 次。这个数字比平均分更能说明结构化输出的稳定性：修复循环会把一次失败掩盖成一个还不错的分数。 异常用例：C71, C72, C73, C74（流水线降级为 error，既不是好方案也不是坏方案，所以不计入最低分）。

| 指标 | 真实模型 | 离线规则 Agent | 对照基线 (naive) |
| --- | ---: | ---: | ---: |
| 硬约束通过率 | 94.2% | 100.0% | 13.8% |
| 平均得分 | 0.8284 | 0.9778 | 0.3014 |
| 平均耗时 | 67.6s (P50) | 0.00s | — |

## 重复测量（3 轮）

同一批用例重复执行，每轮单独算一次「如果只跑一轮会报出什么」：

| 轮次 | 硬约束通过率 | 平均分 |
| ---: | ---: | ---: |
| 1 | 94.2% | 0.8219 |
| 2 | 94.2% | 0.8357 |
| 3 | 94.2% | 0.8276 |
| **极差** | **0.0 pp** | — |

单轮之间的通过率极差是 **0.0 个百分点**。这意味着：两次单轮实验之间小于这个幅度的差异，无法区分是配置变化还是采样噪声。上面的 95% CI 衡量的是「换一批用例会不会翻」，不是「换一轮会不会翻」，两者回答的不是同一个问题。

## 这份数据不能证明什么

- 本报告是同一模型、同一 prompt 的 3 轮重复测量；轮次之间的极差已经列在上表，但结论仍不能外推到其他模型。
- 报告里的 95% 区间是对**用例**做自助法重采样得到的（n=69 时通过率区间约 ±5 个百分点），它衡量的是「换一批同分布的用例，结论会不会翻」，不是「换个模型还成不成立」。两个模型的区间重叠时，不能仅凭点估计宣布谁更好。
- 成本按 `agents/openai_compatible.py` 里的价目表估算，不是账单；只用于相对比较。价目表未收录的模型会退到默认价，可能与实际计费相差数倍。
- 主集共 80 个用例，覆盖 5 城 × 多风格 × 预算/时段压力；本次实际取样见上方用例数，两者都不代表开放域真实需求分布。
- 离线规则 Agent 的 100% 不是「更强」，而是它被设计为不可能违反硬约束；两者的差距说明的是**校验器有判别力**，不是模型好坏排名。

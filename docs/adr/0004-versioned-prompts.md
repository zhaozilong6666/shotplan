# ADR 0004 · prompt 视作代码，带版本与变更记录

- 状态：已接受
- 日期：2026-11-12

## 背景

prompt 通常在项目里以散落的字符串存在，改一个词导致质量下降，却没有任何记录能归因。这会让「我优化了 prompt」变成无法验证的说法。

## 决策

- 所有 prompt 集中在 `agents/prompts.py`，导出 `PROMPT_VERSION` 常量。
- 每次改动在 `PROMPT_CHANGELOG` 追加一条：版本号、日期、改了什么、观测到的结果。
- `RunTrace.prompt_version` 记录每次运行使用的版本，持久化到 SQLite。

## 理由

- 质量退化可以归因到具体改动，这是回归测试有意义的前提。
- 面试时能拿出「v1 → v2 硬约束通过率从 X 到 Y」的证据链，而不是空口讲优化。
- 版本号进 trace，意味着线上任何一次异常输出都能查到当时用的 prompt。

## 后果

- 正向：可归因、可对比、可复现。
- 负向：改 prompt 多一步纪律；版本字符串要与 changelog 保持一致（目前靠人工）。

## 阶段 4 的实验设计

1. 保存当前 `--save-baseline`。
2. 修改 prompt 并递增版本。
3. 在同一评测集上重跑并 `--compare`。
4. 若均分下降超过阈值，CI 失败，回滚或继续调整。

因为判定器不依赖模型（ADR 0002），两个版本的分数是同一把尺子量出来的。

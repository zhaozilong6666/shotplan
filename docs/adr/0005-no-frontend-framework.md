# ADR 0005 · 前端不用框架、不引入构建步骤

- 状态：已接受
- 日期：2026-11-12

## 背景

一个求职项目容易把大量时间花在 React + Vite + 组件库 + 状态管理 + 部署配置上，最后 Agent 逻辑反而很薄。而招聘方点开仓库，最想看的是系统怎么运转、质量怎么保证。

## 决策

`web/` 用原生 HTML + CSS + JavaScript，无 npm、无构建、无 CDN。API 直接以 `FileResponse` 提供这三个静态文件。

## 理由

- 复杂度预算留给真正有区分度的部分：校验器、评测、trace、修复循环。
- 任何人都能在不看构建文档的情况下读懂界面代码，`git clone` 后起一个服务就能看到效果。
- 界面本身就是可交互的论证：切换「规则 Agent / 对照基线」，能直观看到同一需求下哪些约束被违反。

## 后果

- 正向：零构建、零依赖、启动快；`app.js` 里对输出做了 HTML 转义，避免把模型输出直接注入 DOM。
- 负向：没有组件复用、状态管理和类型检查；界面复杂后维护成本会上升。
- 缓解：界面职责被严格限制为「提交 brief + 展示四种视图」，业务逻辑一律不进前端。

## 备选方案

React + Vite（更贴近生产实践，但会稀释项目重点，并引入 node 工具链）；Jupyter Notebook 展示（适合数据分析项目，不适合展示一个可运行服务）。

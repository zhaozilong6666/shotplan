# ADR 0011 · 对照实验优先于归因推断

- 状态：已采纳
- 日期：2026-11-13
- 相关：[0008 模糊测试与性能基准进门禁](0008-fuzz-and-benchmark-gates.md)、[0010 盲测挑战集独立存放](0010-holdout-challenge-set.md)

## 背景

v0.8.0 的 [http-load.md](../http-load.md) 测到 4 个 uvicorn worker 比 1 个还慢，并写下：

> 4 个 uvicorn worker 抢的是同一个 SQLite 文件，WAL 同一时刻只允许一个写者，跨进程写锁与进程协调开销会盖过并行收益。

机制解释听起来合理，但它是**从一次观测反推因果**，没有做过任何干预。只要「去掉写锁」这一步没跑过，就无法排除其它解释：进程协调、上下文切换、CPU 争用、Windows `spawn` 开销，甚至只是样本噪声。

本项目从 ADR 0002 起就主张「判定不交给模型、结论要能被复核」。一个自己写下的因果推断同样应该受这条约束。

## 决策

### 1. 给产品代码加一个最小、可解释的开关

`Settings.persist_runs`（环境变量 `SHOTPLAN_PERSIST_RUNS`，默认 `True`）。为 `0` 时 `/api/plan` 把 `store=None` 传给 `run_plan`，跳过运行历史写入。

- 这是同一份产品代码路径，不是为实验另写一个 app；HTTP、ASGI、JSON 序列化、provider、校验、修复全部不变。
- 它也有独立的产品价值：无状态部署或只读演示可以关掉历史写入。
- 默认行为不变，所有既有测试与门禁不受影响。

### 2. 同一批内交替做干预，多轮取中位数

`evals/worker_lab.py` 对 `1 / 2 / 4 worker × 持久化开 / 关` 共 6 个组合各跑 2 轮、每轮 200 次请求，两组在同一批内交替执行，避免跨批机器负载漂移污染相对比较。报告同时列出**每轮原始值**与中位数，不让中位数被误读成精确常数。

### 3. 先检验「现象是否复现」，再谈归因

判定逻辑（`interpret()`）先算有写入组逐轮的 `4w / 1w` 比值：

| 逐轮情况 | 判定 |
| --- | --- |
| 各轮都 < 1，且关掉写入后 ≥ 1 | `confirmed` 写锁是回落主因 |
| 各轮都 < 1，关掉写入后仍 < 1 | `partially_confirmed` 归因不成立 |
| 各轮都 ≥ 1 | `not_reproduced` 现象没出现，无法检验归因 |
| 有的 < 1、有的 ≥ 1 | `inconclusive` 现象本身不稳定，任何归因都不成立 |
| 关掉写入没有明显提速 | `refuted` 持久化不是主要开销 |

**关键**：结论由数据算出，报告里「与上一版报告的关系」也由 `relation_text()` 随判定动态生成，绝不写死「已证实」或「已证伪」。

### 4. 吞吐继续不进门禁

沿用 ADR 0008。`--check` 只跑两个短场景（1 worker，开 / 关各 20 请求），断言机器无关契约：0 错误、返回合法方案、**开 = 全部落库**、**关 = 0 落库**。最后一条尤其重要：它证明开关真的改变了服务端行为，而不是实验自欺欺人。

## 结果与不稳定记录

最终提交的一批（2 轮 × 200 请求，18 逻辑核 Windows）：

| 项 | 值 |
| --- | ---: |
| 关掉写库后 1 worker 吞吐 | **2.48×** |
| 关掉写库后 2 worker 吞吐 | **3.59×** |
| 有写入组 4w / 1w（逐轮） | 0.86 / 0.92（中位数 0.89） |
| 关掉写入后 4w / 1w | **1.59×** |
| 判定 | `confirmed`（有条件的） |

因此 v0.8.0 的写锁归因**在本批数据下得到支持**，不做推翻。但必须记录：另一次独立探针（单轮 150 请求）里，有写入组的 4 worker 反而比 1 worker 快 **2.42×**，「回落」根本没出现；按同一套判定逻辑会得到 `inconclusive` / `not_reproduced`。

**稳定复现的只有「同步写库是最大单项开销」这一条。**「写锁导致回落」依赖负载条件，只能作为有条件的定性结论，不写成普适规律。这正是把逐轮原始值与判定矩阵一并公开的原因。

## 后果

**好处**：一个可被干预、可被证伪的性能结论；`SHOTPLAN_PERSIST_RUNS` 成为可用的部署选项；门禁验证的是开关语义而不是机器速度。

**代价**：CI 多一道门禁（第 14 道，两次短服务启动约 4 秒）；仓库多一份实验脚本、一份快照、一份报告与这条 ADR。

**边界**：单机 loopback、离线 provider、小样本；绝对值跨运行可差数倍，只能看同一批内的相对关系。运行历史是可观测性与回归追溯的基础，实验结论不是说「应该删掉历史」，而是说**写入应该异步化 / 批量化**，不要留在同步关键路径上。

## 验证

```bash
python -m evals.worker_lab --check   # CI 门禁：开关语义
python -m evals.worker_lab --write  # 重跑完整矩阵
python -m pytest tests/test_worker_lab.py -q
```

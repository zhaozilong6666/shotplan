# ADR 0006 · 评分必须跨 Python 版本逐位一致

- 状态：已接受
- 日期：2026-11-12
- 触发：首次推送 GitHub 后 CI 在 Python 3.10 / 3.11 失败，3.12 / 3.13 通过

## 背景

`agents/validator.py` 用 `sum(SCORE_WEIGHTS[k] * v for k, v in scores.items())` 计算总分。CI 矩阵覆盖 3.10–3.13，第一次运行出现：

```
FAILED tests/test_validator.py::test_perfect_plan_has_no_issues_and_full_score
AssertionError: assert 1.0000000000000002 == 1.0
```

同一份代码、同一份输入，3.10/3.11 得 `1.0000000000000002`，3.12/3.13 得 `1.0`。原因是 **Python 3.12 改进了内置 `sum()` 的浮点求和实现（补偿求和）**，而 3.10/3.11 是朴素累加。本地只跑了一个解释器版本，所以这个差异在推送前完全没暴露。

这不是「测试写得太严」而已：评分会写进评测报告、对照基线、回归阈值判断和前端展示。如果分数随解释器版本漂移，那么「对照组是否追上正式方案」这类结论就不再可比，评测体系的核心论证会被削弱。

## 决策

1. 加权总分用 `math.fsum()`（自 Python 3.x 起即为精确求和，不依赖 `sum()` 的实现变化）。
2. 总分与五个分项统一 `round(..., SCORE_DECIMALS)`，`SCORE_DECIMALS = 6` 定义在 `agents/validator.py`，对外只暴露规整后的值。
3. `evals/scorers.py` 的所有浮点聚合同步改用 `fsum()`，再按原有 4 位小数输出。
4. 新增契约测试：断言分数等于自身规整值、且等于 `fsum(权重 × 分项)` 的规整结果，使实现无法悄悄退化回 `sum()`。
5. CI 的 4 版本矩阵保留，作为该约束的持续验证。

## 理由

- 评测体系的前提是「同一输入 → 同一分数」，解释器版本属于必须被消除的变量。
- 修复落在**产生指标的那一层**，而不是放宽断言；断言仍要求满分严格等于 `1.0`，因此测试继续能抓到真实的评分回归。
- 6 位精度远小于业务上有意义的分差（阈值粒度 0.01 起），不会因为截断掩盖退化。
- 有 ADR 和契约测试，面试时能把它讲成一次「CI 发现的真实工程问题」，而不是一句「改了下浮点」。

## 后果

- 正向：报告、基线、阈值判断在 3.10–3.13 上逐位一致；矩阵 CI 变成真正的兼容性门禁。
- 负向：`scores` 字典里的值不再是任意精度浮点，若将来需要更高分辨率的指标，要显式调整 `SCORE_DECIMALS` 并重刷基线。
- 缓解：常量集中定义，契约测试会在有人绕过规整时失败。

## 备选方案

- **把断言改成 `pytest.approx(1.0)`**：最省事，但把问题藏进测试，指标本身仍会漂移，报告和基线仍不可比 —— 拒绝。
- **CI 只跑一个 Python 版本**：消除症状而非原因，也削弱了兼容性证明 —— 拒绝。
- **改用 `Decimal` 全链路**：精确但侵入大，需要改造知识库与前端序列化，当前收益不抵成本 —— 暂不采用。

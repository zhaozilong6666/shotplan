# ADR 0003 · 精确检索而非向量数据库

- 状态：已接受
- 日期：2026-11-12

## 背景

AI 应用项目里几乎默认会出现向量库 + embedding + 相似度检索。但本项目的知识库只有 8 个地点、5 种风格，且检索结果必须满足精确约束（是否室内、是否收费、标签是否匹配、是否被用户排除），并要求每条都能在最终方案里被引用。

## 决策

用结构化 JSON + 关键词/标签精确匹配 + 确定性打分排序（`knowledge/tools.py`），不引入向量库、不调用 embedding 服务。

## 理由

- 约束是**精确**的：「排除某地点」「预算上限内」「室内兜底」用相似度检索反而会漏。
- 每条知识都有稳定 id，可以做成 `locations.json#city_wall` 这样的引用，直接支撑溯源校验。
- 完全离线、零成本、结果可复现，同样的输入永远得到同样的候选集。
- 规模不需要向量库：几十条记录的暴力打分比维护一个索引简单得多。

## 后果

- 正向：可解释、可测试、可引用；评测不受检索随机性干扰。
- 负向：不支持自然语言模糊语义（比如「想要清冷一点的感觉」不会自动映射到风格），知识库扩容到几千条后需要重新评估。
- 缓解：风格与偏好通过 `suitable_tags` 做标签映射；路线图阶段 4 若接入真实模型，可让模型把自然语言偏好先翻译成标签，检索层仍保持确定性。

## 备选方案

向量库 + RAG（对大文档合适，但在这里会引入不可复现性，且无法保证硬约束）；直接把知识库塞进 prompt（可行，但无法做候选过滤与引用校验，且 token 随规模增长）。

## 附带决策：知识库人工整理

数据不含实时票价与客流，是刻意的。项目要论证的是「约束与评测」，不是「数据抓取」。把不可控的外部数据引进来，会让评测结论随第三方数据变化而失去可比性。
